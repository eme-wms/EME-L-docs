# Класс DBWatch

Класс `DBWatch` в языке EME-L реализует «дозор базы данных» — механизм обнаружения изменений записей, полей и строк между двумя точками выполнения сценария. Объект накапливает список наблюдаемых объектов, а затем за одно обращение возвращает текстовый отчёт обо всех изменившихся элементах. Применяется, например, для защиты от задвоения ключей при конкурентной записи: до транзакции формируется снимок заинтересованных полей, а после открытия транзакции вызывается `Check()` — если отчёт пуст, можно писать, иначе данные нужно перечитать.

Объект класса `DBWatch` создаётся через `Object()` и не привязан к контексту диалога или браузера — это самостоятельный класс без аргументов конструктора.

## Создание объекта

```EME-L
'Создать дозор базы данных'
DBWatch = Object("DBWatch");
```

Конструктор не принимает аргументов и создаёт объект с пустым списком наблюдения и выключенными счётчиками добавленных строк.

## Наблюдение за изменениями

Методы группы `Watch*` регистрируют объекты базы данных в списке дозора. Наблюдение можно установить на запись целиком, на отдельное поле, на строку в записи или на поле в конкретной строке. Идентификатором записи/поля может служить целое число (номер), строка (наименование) или объект `CEMERec` / `CEMEFld`. При повторной установке наблюдения за тем же объектом более детальные наблюдения (строки внутри поля) сбрасываются.

| Метод | Аргументы | Возвращает | Описание |
|-------|-----------|------------|----------|
| `WatchRecord(arg0)` | arg0: Integer/String/CEMERec | Empty | Наблюдение за записью в целом. Сбрасывает ранее установленные наблюдения за полями и строками этой записи. |
| `WatchField(arg0, arg1)` | arg0: Integer/String (запись), arg1: Integer/String (поле) | Empty | Наблюдение за полем. Если наблюдается вся запись — игнорируется. |
| `WatchField(arg0)` | arg0: CEMEFld | Empty | Наблюдение за полем через объект поля; запись и номер поля извлекаются из `CEMEFld`. |
| `WatchLine(arg0, arg1)` | arg0: Integer/String (запись), arg1: Integer (строка) | Empty | Наблюдение за строкой записи. Если наблюдается вся запись — игнорируется. |
| `WatchLine(arg0)` | arg0: CEMERec | Empty | Наблюдение за текущей строкой через объект записи. |
| `WatchFieldLine(arg0, arg1, arg2)` | arg0: Integer/String (запись), arg1: Integer/String (поле), arg2: Integer (строка) | Empty | Наблюдение за полем в конкретной строке. Если наблюдается вся запись или всё поле — игнорируется. |
| `WatchFieldLine(arg0)` | arg0: CEMEFld | Empty | Наблюдение за полем в конкретной строке через объект поля. |
| `UnwatchAll()` | — | Empty | Снимает все объекты с наблюдения и очищает внутренние структуры. Вызывается автоматически при уничтожении объекта. |

> Поля переменной длины (VLF) нельзя проверить на модификацию. Попытка установить наблюдение за VLF-полем через `WatchField` или `WatchFieldLine` вызывает ошибку ядра.

## Проверка и отладка

| Метод | Аргументы | Возвращает | Описание |
|-------|-----------|------------|----------|
| `Check()` | — | String | Возвращает многострочный текст с перечнем изменившихся объектов. Пустая строка — изменений нет. Каждая строка отчёта содержит наименования записи и поля, например `Изменено поле [Рег.No] в записи [Документы]`. |
| `GetContent()` | — | String | Возвращает структурированное содержимое дозора для отладки. Форматы: запись — `{[Наименование]}`; поле — `{[Запись],[Поле]}`; строка записи — `{[Запись],Номер}`; поле в строке — `{[Запись],[Поле],Номер}`. |

## Счётчики добавленных строк

Отдельный механизм — накопительные счётчики добавленных строк для каждой записи. Счётчики включаются парой `TurnOnAppendedCounters` / `TurnOffAppendedCounters`: при включении фиксируется снимок текущего количества строк, при выключении разница между снимком и текущим количеством добавляется к накопленному значению. Используется для учёта строк, добавленных за период между двумя операциями.

| Метод | Аргументы | Возвращает | Описание |
|-------|-----------|------------|----------|
| `ResetAppendedCounters()` | — | Empty | Обнуляет счётчики всех записей и пересоздаёт внутренний массив под текущее количество записей в базе. |
| `TurnOnAppendedCounters()` | — | Empty | Включает механизм счётчиков. При первом включении инициализирует массив и сохраняет снимок количества строк. Повторный вызов генерирует ошибку. |
| `TurnOffAppendedCounters()` | — | Empty | Выключает механизм и прибавляет к счётчикам разницу между текущим количеством строк и снимком. Если счётчики не были включены — ошибка. |
| `GetAppendedCounters(arg0)` | arg0: Array/Map (по ссылке) | Empty | Записывает значения счётчиков в переданный контейнер. Для `Array` заполняет все индексы, для `Map` — только ненулевые значения (ключ — номер записи). Иной тип вызывает ошибку. |

## Примеры

Контроль изменений записи по наименованию и отладка содержимого:

```EME-L
DBWatch = Object("DBWatch");
DBWatch.WatchRecord("Товарная единица");
DBWatch.WatchField("Документы", "Рег.No");
DBWatch.WatchLine("Строки документа", 12);
DBWatch.WatchFieldLine("Строки документа", "@Заголовок", 12);
Content = DBWatch.GetContent();
'Content — структурированный список наблюдаемых объектов'
```

Защита от задвоения SSCC при конкурентной записи: поле наблюдения задано через объект `CEMEFld`, проверка выполняется после открытия транзакции.

```EME-L
'Создать дозор и подключить ядро'
DBWatch = Object("DBWatch");
is_db_watch(1);
'Поле, которое должно остаться неизменным'
DBWatch.WatchField(r_SSCC.GetPalletIDFld());

'Сначала вне транзакции ищем все SSCC'
bNeedCreate = FindSSCC(arrSSCC, r_SSCC);

If (bNeedCreate)
    'Открыть транзакцию и проверить, что поле не изменилось'
    is_transaction(1, "Создание новых SSCC");
    is_db_watch(-1);
    If (DBWatch.Check() != "")
        'Поле изменилось — перечитать данные'
        bNeedCreate = FindSSCC(arrSSCC, r_SSCC);
    End If
    If (bNeedCreate)
        CreateSSCC(arrSSCC, r_SSCC);
    End If
End If
```
