# Класс Atom

Класс `Atom` в языке EME-L реализует примитив атомарной синхронизации для защиты от псевдопараллельных вычислений. Связывается с глобальной целочисленной переменной через ссылку и предоставляет методы для её атомарного захвата (`Lock`), освобождения (`UnLock`) и проверки (`Check`) без изменения значения.

Применяется в системе EME.WMS для защиты обработчиков кнопок и таймеров от взаимных состояний гонки: если один обработчик уже захватил атом, другой, обратившийся к тому же общему ресурсу, получает отказ и завершается досрочно.

> Класс `Atom` решает конкретную задачу — взаимоисключение между псевдопараллельными обработчиками в пределах одного процесса EME-L. Это не мьютекс операционной системы и не синхронизация между разными процессами.

## Создание объекта

```EME-L
'Глобальная переменная-флаг: модифицируется по ссылке в Object("Atom")'
ATOM_TASK = 0;

objAtom = Object("Atom", RefOf ATOM_TASK);
```

Конструктор принимает один обязательный аргумент — ссылку на глобальную целочисленную переменную (`VT_I4`). Переменная обязана быть объявлена заранее и иметь тип «целое число»; передавать в конструктор можно только ссылку, полученную через `RefOf`.

Если на момент создания объекта значение связанной переменной уже равно `1`, объект переходит в **режим только для чтения**: методы `Lock` и `UnLock` возвращают `FALSE`, не изменяя значение переменной. Метод `Check` в этом режиме продолжает работать и отражает фактическое состояние переменной. Режим фиксируется на всё время жизни объекта.

## Методы

| Метод | Аргументы | Возвращает | Описание |
|-------|-----------|------------|----------|
| `Lock()` | — | Boolean | Проверяет и активирует связанную переменную. Если переменная равна `0` — устанавливает её в `1` и возвращает `TRUE`. Если уже не `0` — возвращает `FALSE`, ничего не меняя. |
| `UnLock()` | — | Boolean | Деактивирует связанную переменную, устанавливая её в `0`. В режиме записи возвращает `TRUE`. |
| `Check()` | — | Boolean | Проверяет состояние переменной без изменения. `TRUE` — переменная деактивирована (`0`), `FALSE` — активирована (не `0`). |

В **режиме только для чтения** методы `Lock` и `UnLock` всегда возвращают `FALSE`, не затрагивая переменную.

## Поведение при уничтожении

При уничтожении объекта (например, при выходе из метода, где он был создан как локальная переменная) деструктор автоматически сбрасывает связанную переменную в `0` — но только если объект находится в режиме записи. Объект в режиме только для чтения оставляет переменную без изменений.

Это означает, что повторный захват через новый `Object("Atom", RefOf VAR)` обычно не требуется после выхода предыдущего обработчика: переменная уже освобождена деструктором.

## Примеры

Защита обработчика таймера от повторного входа — если таймер сработал, пока предыдущий обработчик ещё выполняется, новый вызов завершается досрочно:

```EME-L
'ATOM_TIMER_UPDATE — глобальная переменная-флаг'
ATOM_TIMER_UPDATE = 0;

TimerUpdate_OnTimer()
{
    'Попытка захватить атом; FALSE — уже занято, выходим'
    If (~Object("Atom", RefOf ATOM_TIMER_UPDATE).Lock())
        Return;
    End If

    'Проверка, что контекст ещё валиден'
    If (~Object("Atom", RefOf ATOM_CONTEXT).Check())
        Return;
    End If

    'Тело обработчика; при выходе деструктор атома освободит переменную'
    ReloadData();
}
```

Комбинированная защита двух раздельных ресурсов через два атома — один для контекста диалога, второй для процедуры обновления:

```EME-L
'Глобальные переменные для атомов'
ATOM_CONTEXT = 0;
ATOM_TIMER_UPDATE = 0;
ATOM_INPUT_LIST = 0;

Dialog_OnInit()
{
    'Захват контекста на время работы диалога'
    If (~Object("Atom", RefOf ATOM_CONTEXT).Lock())
        Return;
    End If

    'Дальнейшая инициализация...'
}
```

Проверка состояния без захвата — метод `Check` полезен, когда нужно узнать, активен ли другой обработчик, не блокируя его:

```EME-L
objAtom = Object("Atom", RefOf ATOM_TASK);
If (objAtom.Check())
    'Переменная свободна — можно действовать'
Else
    'Переменная занята другим обработчиком'
End If
```
