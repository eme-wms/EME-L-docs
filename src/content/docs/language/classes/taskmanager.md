# Класс TaskManager

Класс `TaskManager` в языке EME-L — диспетчер задач для управления асинхронным выполнением методов EME-L классов в отдельных потоках. Предоставляет механизм создания пула рабочих потоков, добавления задач на выполнение и запуска их параллельного исполнения. Каждая задача представляет собой вызов метода указанного EME-L класса с заданными аргументами. Задачи могут выполняться только локально или только по сети в зависимости от установленного режима.

Поддерживает синхронизацию через критическую секцию для защиты разделяемых данных при параллельном выполнении. Используется в прикладных скриптах EME-L для организации параллельной обработки данных, выполнения фоновых операций и распределения вычислительной нагрузки между потоками.

Объект класса `TaskManager` создаётся через `Object()` и не привязан к контексту диалога или браузера — это самостоятельный класс для организации параллельного выполнения. Внутри вызываемого метода EME-L класса доступен объект текущей задачи (CIName=`CITask`), через который можно получить ссылку на родительский диспетчер и задать текстовое описание хода выполнения.

> **Внимание: условная компиляция по версии ядра.** В C++ реализация класса (`i_TaskManager.cpp`) разделена директивой `#if LAST_VERSION < MAKE_VERSION(52, 0)`:
>
> - **Версии ядра ниже 52.0** (сборки с `KERNEL_12_00`): полный диспетчер задач — три конструктора, методы `AddLocalTask`, `RunTasks`, `EnterSection`, `LeaveSection`, а также вспомогательные классы `CEMELTask`/`CITask`. Описание ниже в разделах «Добавление и запуск задач» и «Объект текущей задачи (CITask)» относится к этому варианту.
> - **Версии ядра 52.0 и выше**: класс редуцирован до заглушки — доступен только один конструктор без аргументов и методы `EnterSection`/`LeaveSection`, использующие внутреннюю `CRITICAL_SECTION`. Методы `AddLocalTask`, `RunTasks` и вспомогательный класс `CITask` **отсутствуют**. Конструктор с аргументами вызывает `too_many()`.
>
> Регистрация `REGISTRY_EMEL_CLASS(TaskManager, …)` также обёрнута в `#ifdef KERNEL_12_00` — вне этой сборки класс не экспортируется в EME-L вообще. Описание в `REGISTRY` соответствует «полной» реализации и не упоминает редукцию в v52.0+; это зафиксировано в `CPP_DISCREPANCIES_REPORT.md`.

## Создание объекта

### Версии ядра ниже 52.0

Класс `TaskManager` имеет три конструктора — по числу аргументов от 0 до 2.

```EME-L
'Конструктор без аргументов — параметры по умолчанию'
objTM = Object("TaskManager");
```

```EME-L
'Конструктор с размером пула локальных потоков'
objTM = Object("TaskManager", 4);
```

```EME-L
'Конструктор с размером пула и режимом выполнения'
objTM = Object("TaskManager", 4, "LOCAL");
```

Конструктор без аргументов создаёт диспетчер с параметрами по умолчанию. При указании размера пула устанавливается количество рабочих потоков в локальном пуле. Режим `"LOCAL"` ограничивает выполнение локальными потоками, `"NET"` — сетевым выполнением. При более чем двух аргументах вызывается ошибка `too_many()`.

### Версии ядра 52.0 и выше

Доступен только один конструктор:

```EME-L
'Единственный доступный конструктор в v52.0+ — без аргументов'
objTM = Object("TaskManager");
```

Любые аргументы приводят к ошибке `too_many()`. Объект создаёт собственную критическую секцию, но не имеет пула потоков и не выполняет задачи.

## Добавление и запуск задач

> Раздел относится только к версиям ядра ниже 52.0. В v52.0+ методы отсутствуют.

| Метод | Аргументы | Возвращает | Описание |
|-------|-----------|------------|----------|
| `AddLocalTask(className, methodName)` | className: String, methodName: String | Empty | Добавляет локальную задачу на выполнение указанного метода EME-L класса без дополнительных аргументов. |
| `AddLocalTask(className, methodName, arg1, ..., argN)` | className: String, methodName: String, arg1..argN: любой тип | Empty | Добавляет задачу с произвольным числом аргументов, передаваемых вызываемому методу. Минимум 2 обязательных аргумента (имя класса и метода); далее — необязательные параметры вызываемого метода. |

`AddLocalTask` добавляет задачу в очередь диспетчера. Фактическое выполнение происходит только при вызове `RunTasks`. Задача всегда выполняется в режиме `TASKMODE_LOCAL_ONLY`, когерентность отключена. При менее чем двух аргументах вызывается ошибка `too_rare()`.

| Метод | Аргументы | Возвращает | Описание |
|-------|-----------|------------|----------|
| `RunTasks()` | — | String | Запускает все добавленные задачи на параллельное исполнение и ожидает их завершения. |

**Возвращаемое значение `RunTasks`:**

| Сценарий | Возвращаемое значение |
|----------|----------------------|
| Успешное выполнение всех задач | Пустая строка |
| Прерывание пользователем | `"Прервано пользователем"` |
| Ошибки в одной или нескольких задачах | Многострочная строка; каждая строка имеет формат `ЗадачаN: инфо (ошибка)`, где `N` — индекс задачи, `инфо` — последний заданный через `SetInfo` текст, `ошибка` — сообщение об ошибке. |

## Синхронизация

Методы `EnterSection`/`LeaveSection` доступны в обеих ветвях условной компиляции, но используют разные внутренние объекты критической секции.

| Метод | Аргументы | Возвращает | Описание |
|-------|-----------|------------|----------|
| `EnterSection()` | — | Empty | Входит в критическую секцию диспетчера задач для синхронизации доступа к разделяемым ресурсам. Блокирует выполнение других потоков, пытающихся войти в эту же секцию, до вызова `LeaveSection`. |
| `LeaveSection()` | — | Empty | Выходит из критической секции диспетчера задач. Разблокирует доступ для других потоков, ожидающих входа в эту секцию. |

Критическая секция — это единая секция на объект `TaskManager`. В версиях ниже 52.0 она разделяется потоками пула, выполняющими задачи. В v52.0+ критическая секция остаётся рабочей (на основе `CRITICAL_SECTION`), но без пула потоков практическое применение ограничено внешней синхронизацией из скрипта. Каждый вызов `EnterSection` должен быть парен с соответствующим `LeaveSection`.

## Объект текущей задачи (CITask)

> Раздел относится только к версиям ядра ниже 52.0. В v52.0+ класс `CITask` не компилируется.

Внутри метода EME-L класса, вызванного через `AddLocalTask`, доступен объект текущей задачи (CIName `CITask`). Этот объект не создаётся через `Object()` — он передаётся исполняющей системой в нулевой аргумент метода (`args[0]`, тип `VT_NULL` с `byref` на `CITask*`). Методы объекта:

| Метод | Аргументы | Возвращает | Описание |
|-------|-----------|------------|----------|
| `GetTaskManager()` | — | Ссылка на TaskManager | Возвращает объект диспетчера задач, управляющего выполнением текущей задачи. |
| `SetInfo(info)` | info: String | Empty | Устанавливает текстовую информацию о текущей задаче, отображаемую в окне диспетчера задач и используемую в журнале ошибок `RunTasks`. |

Объект `CITask` в скриптах EME-L принимает имя, заданное в сигнатуре метода (обычно `Task`). Реальный пример использования обоих методов — класс `QAModule.QATasks` (см. раздел «Примеры»).

## Константы

Значения режима выполнения, задаваемые вторым аргументом конструктора `TaskManager(размерПула, режим)`:

| Строковое значение | Внутренняя константа | Описание |
|--------------------|----------------------|----------|
| `"LOCAL"` | `TASKMODE_LOCAL_ONLY` | Задачи выполняются только локально. |
| `"NET"` | `TASKMODE_NET_ONLY` | Задачи выполняются только по сети. |

Любое иное значение приводит к ошибке `Неизвестное значение для параметра task mode`. Эти значения применимы только в версиях ниже 52.0, где доступен конструктор с двумя аргументами.

## Примеры

Шаблон диспетчера (создание объекта `TaskManager` и вызов `AddLocalTask`/`RunTasks`) ниже синтетический — в поставляемой базе конструкт `Object("TaskManager"` в скриптах не встречается. Однако API объекта задачи (`CITask`) используется в реальном классе `QAModule.QATasks` (см. пример ниже), методы которого вызываются через `AddLocalTask` из вызывающего кода вне выгрузки скриптов.

Параллельное выполнение методов двух классов:

```EME-L
'Создать диспетчер с пулом из 4 потоков в локальном режиме'
objTM = Object("TaskManager", 4, "LOCAL");

'Добавить задачи — метод ProcessData класса MyWorker без аргументов'
objTM.AddLocalTask("MyWorker", "ProcessData");

'Добавить задачу с аргументами — метод Export класса ReportHandler'
objTM.AddLocalTask("ReportHandler", "Export", "D:\\Data\\out.txt", 100);

'Запустить все задачи и дождаться завершения'
strResult = objTM.RunTasks();

If (strResult <> "")
    is_message("Ошибки выполнения", strResult);
End If
```

Использование критической секции внутри метода, вызываемого задачей:

```EME-L
'Внутри метода класса MyWorker — задача получила TaskManager в args[0]'
objTM = args[0].GetTaskManager();

'Защита разделяемого ресурса'
objTM.EnterSection();
arrShared.SetAt("key", Value);
objTM.LeaveSection();

'Обновить описание хода выполнения для окна диспетчера'
args[0].SetInfo("Обработано записей: " + nDone);
```

### Реальный пример: `QAModule.QATasks` (поставляемая база)

Класс `QAModule.QATasks` — реальный потребитель API `CITask`. Его методы (`RunGlobal`, `RunLocal` и обёртки `RunGlobalGlossary`/`RunLocalHistory`) вызываются через `AddLocalTask` и принимают объект задачи первым аргументом. Внутри методов используется `Task.SetInfo()` для индикации хода выполнения и `Task.GetTaskManager().EnterSection()`/`LeaveSection()` для защиты слияния результатов запроса в разделяемый объект `Query`:

```EME-L
RunGlobal(QueryName, Task AS "Invariant", Query AS "Query", HandShakingQuery AS "Query", QueryLotKeyIn, BranchRef)
{
    Branch = Object("dsDB", "Branch");
    Branch.SetLine(BranchRef);

    QueryLotKey = QueryLotKeyIn;
    IPAddress = Branch.GetIP();
    Port = Branch.GetPort();

    'Индикация хода выполнения — текст виден в окне диспетчера'
    Task.SetInfo(Branch.GetTextCode() + ": " + "запрос к " + IPAddress);

    Object("System").InitQueryCache();
    GlobalQuery = Object("Query", QueryName);
    GlobalQuery.Execute();

    Task.SetInfo(Branch.GetTextCode() + ": " + "обработка запроса");

    'Синхронизация доступа к разделяемому объекту Query'
    TaskManager AS "Invariant" = Task.GetTaskManager();
    TaskManager.EnterSection();
    Query.Merge(GlobalQuery);
    Line = HandShakingQuery.AddLine();
    HandShakingQuery.PutData("Filial", Line, Branch.GetCode());
    TaskManager.LeaveSection();

    Task.SetInfo(Branch.GetTextCode() + ": " + "запрос завершен");
}
```

Шаблон показывает типичное применение: задача выполняет удалённый/локальный запрос к филиалу, затем под критической секцией диспетчера сливает результат в общий объект `Query` и фиксирует квитирование в `HandShakingQuery`. Поисковый ключ `QueryLotKey`, `IPAddress`, `Port` и `PalletID` сохраняются в полях класса для последующего опроса вызывающим кодом.
