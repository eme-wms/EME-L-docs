# Класс ExpImp64

Класс `ExpImp64` в языке EME-L — это 64-разрядный интерфейс для чтения файлов ядерного экспорта/импорта системы EME. Предоставляет методы для открытия экспортных файлов, последовательного извлечения записей с построчным чтением данных в объекты `Query`, а также получения метаданных файла (версия, филиал, дата, время).

В отличие от базового класса `ExpImp`, `ExpImp64` поддерживает **поэтапное чтение записи**: сначала извлечение структуры методом `ExtractNextRecord`, затем чтение порциями строк методом `ExtractNextLines`. Также предоставляет доступ к информации о количестве строк в записи и текущей позиции чтения. Класс применяется в скриптах EME-L для программного импорта данных из файлов экспорта, созданных ядром системы или другими филиалами, **с поддержкой 64-битных ссылочных полей**.

Объект создаётся через `Object("ExpImp64")` без аргументов и не привязан к контексту диалога или браузера. Данные из файла читаются во внешний объект `Query`, который передаётся по ссылке в метод `ExtractNextLines`.

## Создание объекта

```EME-L
i_ExpImp = Object("ExpImp64");
```

Конструктор без аргументов (перегрузок нет) создаёт объект с закрытым файлом. Открытие файла выполняется методом `LoadFile`, после чего доступны методы чтения записей и метаданных. Повторный вызов `LoadFile` автоматически закрывает предыдущий открытый файл.

## Открытие файла и управление чтением

| Метод | Аргументы | Возвращает | Описание |
|-------|-----------|------------|----------|
| `LoadFile(filePath)` | filePath: String | String | Открывает файл экспорта EME и проверяет сигнатуру `EXIM`. При успехе возвращает пустую строку; при ошибке — текст сообщения (открытие файла, неверная сигнатура). Если файл уже был открыт, предыдущий закрывается автоматически. |
| `ExtractNextRecord()` | — | Boolean | Извлекает следующую запись из файла и подготавливает структуру полей. `TRUE` (в языке EME-L равно -1) — запись извлечена; `FALSE` (0) — записи закончились. При неверном формате (отсутствие сигнатуры `HDR3` заголовка записи или `HDR4` заголовка поля) генерирует исключение. |
| `ExtractNextLines(query, lineCount)` | query: Query (по ссылке), lineCount: Integer | Empty | Извлекает `lineCount` строк текущей записи и заполняет переданный запрос данными. Перед вызовом необходимо извлечь запись методом `ExtractNextRecord`. Поддерживает специальную обработку полей «Ключи» (64-битное целое, `INT64_ATTRIBUTE`) и «Флаги» (32-битное целое, `INT_ATTRIBUTE`), а также коррекцию атрибутов для ссылочных полей; длины текстовых полей ограничиваются размером поля в базе данных. |
| `GetNoOfLines()` | — | Integer | Общее количество строк в текущей записи, извлечённой методом `ExtractNextRecord`. |
| `GetLine()` | — | Integer | Текущая позиция чтения в записи (0-based) после вызова `ExtractNextLines`. Нумерация начинается с 0. |

### Поведение `ExtractNextLines` по типам полей

Реализация (`PrepareQuery`/`ReadData`/`WriteData`) определяет следующие правила обработки полей:

- **Поля «Ключи»** всегда читаются как 64-битное целое (`INT64_ATTRIBUTE`) независимо от атрибута в файле.
- **Поля «Флаги»** всегда читаются как 32-битное целое (`INT_ATTRIBUTE`).
- **Ссылочные поля** (атрибут `this_is_ref_attr`) приводятся к `INT64_ATTRIBUTE` — 64-битному ключу.
- **Атрибуты `FLAGS_ATTRIBUTE` и `ARRAY_ATTRIBUTE`** приравниваются к `INT_ATTRIBUTE` (читаются как целое число).
- **Массивы ссылок** (`ARRAY_OF_REFERENCE`) пропускаются при подготовке запроса — данные таких полей не импортируются.
- **Текстовые поля** (`TEXT_STRING_ATTRIBUTE`): длина строки ограничивается размером соответствующего поля в базе данных (`get_field_length`); если размер в базе неизвестен или равен нулю, используется значение по умолчанию **256** байт, плюс 1 байт на завершающий символ.
- **Поля нераспознанных типов**: если атрибут не поддерживается ядром, используется фиксированный размер **64** байта.
- **Поля переменной длины** (флаг `VARIABLE_LENGTH_FIELD_BIT`) читаются порционно: для каждой строки из файла сначала считывается 4-байтная длина, затем сами данные. То же верно для полей `DATA_STORAGE_ATTRIBUTE`, если версия файла ≥ `IMPORT_FILE_VERSION4`.

## Метаданные файла

Все методы метаданных требуют предварительно открытого файла методом `LoadFile`, иначе генерируют исключение «Файл не открыт».

| Метод | Аргументы | Возвращает | Описание |
|-------|-----------|------------|----------|
| `GetVersion()` | — | Integer | Версия формата файла экспорта EME. |
| `GetExportType()` | — | String | Тип экспорта: два последних символа имени файла, если статус филиала-источника равен `SYS_EXPORT_STATUS` (системный экспортный файл — например, `"s1"`, `"s2"`). Пустая строка, если файл не является системным. |
| `GetFilialNo()` | — | Integer | Номер филиала, сформировавшего файл экспорта. |
| `GetFilialStatus()` | — | Integer | Код статуса филиала-источника файла экспорта. |
| `GetFileName()` | — | String | Имя файла экспорта из заголовка открытого файла. |
| `GetDate()` | — | DateTime | Дата формирования файла экспорта. |
| `GetTime()` | — | DateTime | Время формирования файла экспорта. |
| `GetRecordName()` | — | String | Имя текущей записи, извлечённой методом `ExtractNextRecord`. Пустая строка, если запись ещё не была извлечена. |

## История предыдущего экспорта

Методы возвращают значения из заголовка текущего файла о предыдущей выгрузке по истории. Требуют открытого файла методом `LoadFile`.

| Метод | Аргументы | Возвращает | Описание |
|-------|-----------|------------|----------|
| `GetPrevFileName()` | — | String | Имя предыдущего файла экспорта по истории. Пустая строка, если информация о предыдущем файле отсутствует. |
| `GetPrevDate()` | — | DateTime | Дата предыдущего файла экспорта по истории. |
| `GetPrevTime()` | — | DateTime | Время предыдущего файла экспорта по истории. |

## Порядок вызова методов

Типичный цикл импорта файла ядерного экспорта EME:

1. `LoadFile(path)` — открыть файл, проверить сигнатуру `EXIM`.
2. В цикле: `ExtractNextRecord()` — извлечь запись; возврат `FALSE` означает конец файла.
3. `GetRecordName()` / `GetNoOfLines()` — опционально, для маршрутизации по типу записи.
4. `ExtractNextLines(query, n)` — заполнить порцию строк в объекте `Query`.
5. Повторять шаг 4, пока `GetLine()` не достигнет `GetNoOfLines()`, затем вернуться к шагу 2.

## Примеры

Открытие файла ядерного экспорта EME и проверка результата:

```EME-L
i_ExpImp = Object("ExpImp64");
Result = i_ExpImp.LoadFile(FileName);
If (Result != "")
    is_message(tr("Импорт файла"), Result, "OK", "STOP");
    Return;
End If
```

Последовательное извлечение записей и строк в объект `Query`:

```EME-L
i_ExpImp = Object("ExpImp64");
Result = i_ExpImp.LoadFile(FileName);
If (Result == "")
    Query = Object("Query");
    Query.Create();

    While (i_ExpImp.ExtractNextRecord())
        'ExtractNextRecord возвращает TRUE, пока есть записи'
        RecordName = i_ExpImp.GetRecordName();

        While (i_ExpImp.GetLine() < i_ExpImp.GetNoOfLines())
            'Заполнить пакет строк в Query'
            i_ExpImp.ExtractNextLines(Query, 100);
            'Query содержит строки — обработать и очистить'
            Query.Delete();
            Query.Create();
        End While
    End While
End If
```

Сверка имени предыдущего файла с последним импортированным (контроль непрерывности цепочки выгрузок):

```EME-L
i_ExpImp = Object("ExpImp64");
Result = i_ExpImp.LoadFile(Folder + FileName);
If (Result == "")
    PrevName = i_ExpImp.GetPrevFileName();
    'PrevName содержит имя предыдущего файла экспорта по истории'
End If
```
