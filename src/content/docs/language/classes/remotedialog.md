# Класс RemoteDialog

Класс `RemoteDialog` в языке EME-L — класс для сериализации состояния диалогового окна и передачи его между клиентом и сервером. Представляет собой снимок диалога, который позволяет заполнять и изменять значения органов управления диалога на сервере без прямого доступа к GUI-объектам.

Объект привязывается к указанному диалогу, а считывание реальных значений органов выполняется при сериализации для передачи на сервер. На стороне сервера скрипт получает десериализованный объект `RemoteDialog`, обращается к органам через `GetControl` или сокращённое имя `C`, меняет их значения методами `Put`/`PutToRow` и управляет доступностью через `Disable`. При обратной десериализации на клиенте изменения автоматически синхронизируются с исходным диалогом.

Используется в прикладных скриптах EME-L для выполнения серверных процедур, требующих доступа к данным диалога, без необходимости передачи самих GUI-объектов.

## Создание объекта

Класс `RemoteDialog` имеет один конструктор — с одним аргументом.

```EME-L
'Конструктор с привязкой к существующему диалогу'
rd = Object("RemoteDialog", dlg);
```

Конструктор принимает ссылку на объект диалога, состояние которого требуется сериализовать. Извлекаются внутренние данные диалога и определяется имя объекта для формирования полных имён органов (формат `«Объект.Орган»`). Само считывание значений органов выполняется позже — при последующей сериализации объекта. Точная сигнатура проверки аргументов: ровно 1 аргумент — `too_many()` при `> 1`, `too_rare()` при `< 1`.

## Доступ к органам управления

После десериализации на сервере орган диалога представляется объектом `CRemoteControl` (внутренний класс C++, недоступный для прямого создания через `Object()`). Ссылка на него возвращается методами доступа, после чего через неё вызываются `Put`, `PutToRow` и `Disable`.

| Метод | Аргументы | Возвращает | Описание |
|-------|-----------|------------|----------|
| `GetControl(arg0)` | arg0: String (полное имя) | CRemoteControl | Сериализованный орган диалога по полному имени в формате `«Объект.Орган»`. Предназначен для вызова на стороне сервера с десериализованным объектом. При наличии привязанного диалога генерируется внутренняя ошибка `internal_error()`. Если орган с указанным именем не найден в снимке — ошибка `smart_error("Не найден орган диалога: %s", Name)`. |
| `C(arg0)` | arg0: String (короткое имя) | CRemoteControl | То же по сокращённому имени органа. Автоматически дополняет имя именем объекта диалога, формируя полное имя `«Объект.Орган»`. Реализация делегирует в `GetControl` с конкатенацией `m_ObjectName + "." + arg0`. |

`GetControl` преднамеренно защищён от вызова на стороне клиента: проверка `if (m_Dialog) internal_error()` гарантирует, что орган можно получить только из десериализованного снимка, а не из «живого» диалога.

## Методы органа CRemoteControl

Методы вызываются на ссылке, возвращённой `GetControl` или `C`. Все возвращают пустое значение (`null`). Каждый вызов устанавливает внутренний флаг модификации `m_Modify = TRUE`, который определяет, будет ли орган записан обратно в диалог при десериализации на клиенте (см. раздел «Синхронизация изменений»).

| Метод | Аргументы | Возвращает | Описание |
|-------|-----------|------------|----------|
| `Put(arg0)` | arg0: любой тип (значение) | Empty | Устанавливает значение сериализованного органа в строку 0. |
| `PutToRow(arg0, arg1)` | arg0: любой тип (значение), arg1: Integer (номер строки) | Empty | Устанавливает значение сериализованного органа в указанную строку таблицы. Нумерация строк с 0. |
| `Disable(arg0)` | arg0: Boolean / `"1"` / `"0"` / `"Да"` / `"Нет"` | Empty | Устанавливает флаг доступности органа «только для чтения» в строке 0. Значение обрабатывается через `variant2boolean`, поэтому принимает любую «булевскую» форму EME-L. |

### Флаг `только_чтение` метода Disable

Аргумент принимает любой «булевский» тип EME-L. Допустимые значения TRUE: `TRUE`, `"1"`, `"Да"`. Допустимые значения FALSE: `FALSE`, `"0"`, `"Нет"`. TRUE — орган доступен только для чтения; FALSE — орган доступен для редактирования. При десериализации на клиенте состояние применяется через `soft_set_edit_read_only` диалога.

## Синхронизация изменений

При сериализации на стороне клиента (есть `m_Dialog`) все органы читаются из диалога, и для каждого сразу же вызывается `ClrModify()` — снимок считается «чистым». На стороне сервера вызовы `Put`/`PutToRow`/`Disable` устанавливают флаг `m_Modify = TRUE` для затронутого органа.

При обратной десериализации на клиенте запись значения органа обратно в диалог выполняется **только для модифицированных органов** (`if (m_Dialog && pControl->IsModify())`). Немодифицированные органы сохраняют свои исходные значения — это снижает накладные расходы и предотвращает перезапись полей, которые сервер не менял.

Для табличных органов, если число строк в снимке (`GetNoOfLines()`) превышает текущее число строк таблицы диалога, недостающие строки автоматически добавляются через `add_table_line()` — сервер может передать больше строк, чем было в исходном диалоге.

## Типы сериализуемых органов

При сериализации на стороне клиента в снимок включаются только органы следующих типов (определяется внутренним флагом `CNTRL_TYPE` органа диалога):

- `CT_EDITOR` — поле ввода/редактора;
- `CT_COMBOBOX` — выпадающий список;
- `CT_BUTTON` — кнопка;
- `CT_RADIOBUTTON` — переключатель.

`CT_*` — это внутренние константы C++ класса `DIALOG_EDITOR_PARAMS`; в EME-L они недоступны как значения и приведены только для справки. Органы других типов (статические подписи, рамки и пр.) в снимок не попадают и не могут быть получены через `GetControl` или `C`. Для табличных столбцов значения считываются и записываются построчно — методы `PutToRow` и строка 0 в `Put`/`Disable` соответствуют строкам связанной таблицы диалога.

## Примеры

Заполнение органа на стороне сервера по полному имени:

```EME-L
'На сервере: rd получен десериализацией аргумента'
ctl = rd.GetControl("Obj.header_field");
ctl.Put("Новое значение");
ctl.Disable(TRUE);
```

То же по сокращённому имени с автоматическим добавлением объекта:

```EME-L
ctl = rd.C("header_field");
ctl.Put("Новое значение");
```

Заполнение табличного органа по строкам (можно передать больше строк, чем было в исходном диалоге — на клиенте они будут добавлены автоматически):

```EME-L
'Установить значение органа в строки 0, 1, 2'
ctl = rd.C("table_column");
ctl.PutToRow("Значение 1", 0);
ctl.PutToRow("Значение 2", 1);
ctl.PutToRow("Значение 3", 2);
```
